CST vs PVST vs MST: how many STP topologies does each run?	<b>CST</b> (802.1D): one topology for all VLANs.<br><b>PVST</b>: one topology per VLAN (high CPU/memory with many VLANs).<br><b>MST</b>: one or more VLANs mapped to an <b>MST instance (MSTI)</b>, one topology per instance.	ch04 mst
Two problems MST solves (DIKTA Q1)	1. <b>Load balancing per VLAN group</b>: VLANs go to instances that can block different links.<br>2. <b>Less CPU and memory</b> than PVST with many VLANs: many VLANs share one instance.<br>Not MAC table scaling, not one-way links, not rogue switches.	ch04 mst dikta
What is an MST region, and how do switches outside it see it?	A group of MST switches with the <b>same name, revision and VLAN-to-instance mapping</b>.<br>Outside switches see the whole region as <b>one virtual switch</b> (so hop counts through the region look like one hop).	ch04 mst
What is the IST, and why does MST send only one set of BPDUs?	The <b>internal spanning tree</b> is always <b>instance 0</b> and runs on every port in the region.<br>Info for the other MSTIs is <b>nested in the IST BPDU</b>, so one set of BPDUs covers all instances.<br>At least 16 instances: 0 is the IST, 1-15 are MSTIs.	ch04 mst
Does the MST root bridge advertise the VLAN-to-instance mappings? (DIKTA Q4)	<b>False.</b> Each switch maps VLANs to instances in its <b>own local config</b>. The IST only carries the BPDUs that build the topology.	ch04 mst dikta
Is the MST configuration version (revision) locally significant? (DIKTA Q5)	<b>False.</b> The revision (plus name and VLAN mapping) must <b>match on every switch in the region</b>. One mismatch puts that switch in a different region.	ch04 mst dikta
MST configuration: the 5 steps and commands	1. <code>spanning-tree mode mst</code><br>2. (opt) <code>spanning-tree mst <i>N</i> priority <i>0-61440 step 4096</i></code> or <code>root primary</code> (24576) / <code>secondary</code> (28672)<br>3. <code>spanning-tree mst configuration</code> → <code>instance <i>N</i> vlan <i>list</i></code> (default: all VLANs in MST0)<br>4. <code>revision <i>N</i></code> (must match in region)<br>5. (opt) <code>name <i>REGION</i></code> (default empty)	ch04 mst config
MST verification commands and what each shows	<code>show spanning-tree mst configuration</code>: name, revision, instance-to-VLAN map.<br><code>show spanning-tree</code>: per MST0/MST1..., no VLAN numbers; priority = priority + instance (e.g. 24577 for MST1).<br><code>show spanning-tree mst [N]</code>: VLANs mapped next to each instance.<br><code>show spanning-tree mst interface <i>X</i></code>: per-instance role/state, edge, boundary, BPDU guard/filter.	ch04 mst verify
