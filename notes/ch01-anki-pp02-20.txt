A switch gets a frame. Which MAC address does it <b>learn from</b>, and which MAC address does it use to <b>forward</b> the frame?	It learns the <b>source</b> MAC (records MAC + port + VLAN in the MAC address table).<br>It forwards using the <b>destination</b> MAC.<br><br>(Layer 3 forwarding uses the destination IP.)	ENCOR ch01 L2-forwarding dikta-miss
Which device shrinks a <b>collision domain</b>, and which device shrinks a <b>broadcast domain</b>?	<b>Switch</b> shrinks the collision domain: each port is its own collision domain, so hosts can run full duplex.<br><b>Router</b> shrinks the broadcast domain: broadcasts don't cross a Layer 3 boundary.<br><br>A hub does neither, it repeats everything out every port.	ENCOR ch01 L2-forwarding
What is <b>unknown unicast flooding</b>?	The destination MAC isn't in the switch's MAC address table, so the switch sends the frame out every port in that VLAN except the one it came in on.	ENCOR ch01 L2-forwarding
Name the four 802.1Q tag fields, their sizes, and the total tag size.	TPID 16 bits (0x8100, marks the frame as 802.1Q)<br>PCP 3 bits (CoS, Layer 2 QoS)<br>DEI 1 bit (can be dropped when bandwidth is contended)<br>VLAN ID 12 bits<br><br>Total: <b>32 bits</b> (4 bytes)	ENCOR ch01 VLAN 802.1Q
Catalyst VLAN ranges: what are VLAN 0, VLAN 1, 2-1001, 1002-1005 and 1006-4094?	0: reserved for 802.1p, can't change or delete<br>1: default VLAN, can't change or delete<br>2-1001: normal range, add/delete/modify<br>1002-1005: reserved, can't delete<br>1006-4094: extended range, add/delete/modify	ENCOR ch01 VLAN
You type <code>vlan 10</code> then <code>name PCs</code>. When does the VLAN actually get created?	Only when you leave VLAN submode: go back to global config or move to another VLAN ID.<br><br>(VLAN name can be up to 32 characters.)	ENCOR ch01 VLAN
What are the three sections of <code>show interfaces trunk</code>?	1. Trunk ports: mode, encapsulation, status, <b>native VLAN</b><br>2. VLANs <b>allowed</b> on the trunk (and allowed + active in the management domain)<br>3. VLANs in <b>STP forwarding state and not pruned</b> (blocked VLANs don't show)	ENCOR ch01 trunk verify
What is the native VLAN, what is the default, and what is the best practice?	Traffic sent or received on a trunk <b>without a tag</b> belongs to the native VLAN. Default is VLAN 1.<br>Set per port: <code>switchport trunk native vlan &lt;id&gt;</code><br><br>Best practice: change it from VLAN 1 (control plane traffic uses VLAN 1) to an <b>unused VLAN</b> with no hosts, and make it <b>match on both ends</b>.	ENCOR ch01 trunk native-vlan
A trunk allows VLANs 10,20,99. You need to add VLAN 30 and type <code>switchport trunk allowed vlan 30</code>. What happens, and what should you type?	The list is <b>overwritten</b>: only VLAN 30 is allowed now, so 10, 20 and 99 lose traffic.<br><br>Use <code>switchport trunk allowed vlan add 30</code> (and <code>remove</code> to take one out).	ENCOR ch01 trunk allowed-vlan
Host A pings Host B. How does A pick the destination MAC when B is on the <b>same subnet</b> vs a <b>different subnet</b>?	Same subnet: ARP for <b>B's</b> IP and use B's MAC.<br>Different subnet: look up the next hop in the routing table (or default gateway), ARP for the <b>next-hop</b> IP and use that MAC.<br><br>The ARP table only holds entries for the local segment, never remote hosts.	ENCOR ch01 L3-forwarding ARP
